# projstat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust terminal dashboard that shows momentum across pinned GitHub repos and names today's pick, to keep a solo maintainer moving.

**Architecture:** Pure logic layer (`metrics`, `format`) with no external crates, fed by a `gh`-CLI data layer (`gh`) parsed into domain types (`model`); `config` + `cache` on disk; a tokio/crossterm event loop (`app`) renders via ratatui (`ui`). Pinned-only; cache shown instantly, refreshed async.

**Tech Stack:** Rust 2024, ratatui 0.30, crossterm 0.28 (event-stream), tokio 1, serde/serde_json, chrono, anyhow/thiserror, clap (derive). Data via `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-31-projstat-design.md` (see also `docs/decisions.md`, `docs/directory-tree.md`, `docs/fm-usage.md`).

## Global Constraints

- Rust edition **2024**. Deps pinned to house style: `ratatui = "0.30"`, `crossterm = "0.28"` (features `["event-stream"]`), `tokio = "1"` (full), `serde`/`serde_json`, `chrono`, `anyhow`, `thiserror`, `clap` (derive).
- **Rendering:** alt-screen only, diff-only repaint through ratatui's `Frame`. **No** manual screen clears, **no** `println!`/raw stdout while the TUI is active. (Flicker prevention.)
- **Pure layer discipline:** `metrics.rs` and `format.rs` use `std` only (primitive inputs, no chrono/serde) so they are `fm`-eligible per `docs/fm-usage.md` and fast to test.
- **Data:** read-only. No write calls to GitHub. All data via `gh` subprocess.
- **Commits:** conventional messages. **No AI attribution / Co-Authored-By lines** (per `~/.claude/CLAUDE.md`). Branch, never commit straight to a default branch.
- `fm`-eligible tasks: every `fm` output passes `cargo check` + the task's unit test before it is kept; two failures ⇒ hand-write. `fm` never writes its own test.

## Review Focus

Inputs the spec implies but that no happy-path test exercises, most-likely-to-bite first. Each has a test added to the owning task.

- **`gh` missing or not authenticated** → startup fails with a clear message, not a panic. (Task 2)
- **A `gh` fetch fails / offline** → that repo is skipped, cached data still shown, app never crashes. (Task 7, Task 8)
- **Repo with no open milestone / milestone with zero issues** → progress 0%, no divide-by-zero, repo still listed and can't falsely win the hero. (Task 3)
- **Malformed or empty `gh` JSON** → parse returns `Err`, not a panic. (Task 7)
- **Pinned repo that doesn't exist (404)** → skipped gracefully with a note, other repos unaffected. (Task 7, Task 8)
